## Setup

### 1. Install Packages

```bash
npm install @yourgpt/copilot-sdk @yourgpt/llm-sdk openai
```

### 2. Get API Key

Get your API key from [platform.openai.com](https://platform.openai.com/api-keys)

### 3. Add Environment Variable

```bash title=".env.local"
OPENAI_API_KEY=sk-...
```

### 4. Usage

```ts
import { generateText } from "@yourgpt/llm-sdk";
import { openai } from "@yourgpt/llm-sdk/openai";

const result = await generateText({
  model: openai("gpt-4o"),
  prompt: "Explain quantum computing simply.",
});

console.log(result.text);
```

### 5. Streaming (API Route)

```ts title="app/api/chat/route.ts"
import { streamText } from "@yourgpt/llm-sdk";
import { openai } from "@yourgpt/llm-sdk/openai";

export async function POST(req: Request) {
  const { messages } = await req.json();

  const result = await streamText({
    model: openai("gpt-4o"),
    system: "You are a helpful assistant.",
    messages,
  });

  return result.toTextStreamResponse();
}
```

## Configuration Options

```ts
import { openai } from "@yourgpt/llm-sdk/openai";

// Custom API key
const model = openai("gpt-4o", {
  apiKey: "sk-custom-key",
});

// With generation options
const result = await generateText({
  model: openai("gpt-4o"),
  prompt: "Hello",
  temperature: 0.7, // Availability depends on model and reasoning settings
  maxTokens: 4096, // Max response length
});
```

## Tool Calling

OpenAI has excellent tool/function calling support:

```ts
import { generateText, tool } from "@yourgpt/llm-sdk";
import { openai } from "@yourgpt/llm-sdk/openai";
import { z } from "zod";

const result = await generateText({
  model: openai("gpt-4o"),
  prompt: "What is the weather in Tokyo?",
  tools: {
    getWeather: tool({
      description: "Get weather for a city",
      parameters: z.object({
        city: z.string().describe("City name"),
      }),
      execute: async ({ city }) => {
        // Your weather API call
        return { temperature: 22, condition: "sunny" };
      },
    }),
  },
  maxSteps: 5, // Allow multiple tool calls
});
```

## Vision (Image Input)

GPT-4o supports image analysis. Send images in your messages:

```ts
const result = await generateText({
  model: openai("gpt-4o"),
  messages: [
    {
      role: "user",
      content: [
        { type: "text", text: "What's in this image?" },
        { type: "image", image: base64ImageData },
      ],
    },
  ],
});
```

## Reasoning model parameters

The beta recognizes GPT-5/GPT-6 and o-series reasoning families. When reasoning is active, it omits unsupported `temperature` values and emits a warning. A request such as `temperature: 0` no longer relies on treating GPT-6 Luna as a legacy sampling model.

The SDK does not disable reasoning automatically to preserve temperature. If your model supports non-reasoning mode and you explicitly want it:

```ts
import { generateText } from "@yourgpt/llm-sdk";
import { openai } from "@yourgpt/llm-sdk/openai";

const result = await generateText({
  model: openai("gpt-6-luna", {
    reasoningEffort: "none",
    onWarning: (message) => console.warn(message),
  }),
  prompt: "Classify this message: I need help changing my password.",
  temperature: 0,
  maxTokens: 128,
});
```

Unsupported reasoning-effort combinations fail before a request. `maxTokens` maps to `max_completion_tokens` for reasoning Chat requests, `max_tokens` for legacy Chat, and `max_output_tokens` for Responses.

OpenAI-compatible servers with different parameter semantics can opt out with provider option `parameterPolicy: 'passthrough'`; this gives your application responsibility for compatible parameters. `onWarning` lets you observe normalization. See [compatibility fallback](/docs/providers/fallback#compatibility-fallback-without-retries) for advancing past a narrowly identified parameter error without retrying the same invalid request.

## Responses, image tools, and audio

Use `api: 'responses'` to select Responses explicitly. The default `api: 'auto'` preserves compatibility routing, including Chat defaults for custom endpoints. See the [Responses guide](/docs/llm-sdk/responses) for stored/stateless continuation and the [cache options](/docs/advanced/prompt-caching) supported by this beta.

Native [image tool results](/docs/tools/image-results) require Responses on OpenAI; ordinary image inputs in user messages are a separate feature. [Speech generation](/docs/llm-sdk/speech) and [transcription](/docs/llm-sdk/transcription) use separate audio model factories. Native Decisions and realtime calls remain [pending](/docs/beta#still-pending).
