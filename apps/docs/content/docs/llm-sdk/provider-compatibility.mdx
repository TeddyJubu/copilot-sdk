---
title: Testing provider compatibility
description: Verify text, streaming, tools, structured output, and usage against your provider account
---

Model support depends on the model, endpoint, account access, and requested settings. Run the opt-in checks against the SDK source you intend to ship. A successful text request alone does not verify tool continuation, structured output, or billing usage.

## Repeatable live checks

Build the workspace SDKs first. Provide `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` privately in the test process environment. These tests make billable API calls with synthetic prompts. They require an explicit model list and never run as part of the ordinary unit-test command.

From the repository root:

```bash
pnpm build:sdk

RUN_PROVIDER_MATRIX=1 \
PROVIDER_MODELS='openai:gpt-6-luna,anthropic:claude-haiku-5-5' \
node packages/llm-sdk/test/live/provider-matrix.cjs
```

Each model runs through `generateText`, `streamText`, and `runtime.chat` with streaming enabled and disabled. The cases check plain text, JSON mode, native JSON Schema output, a function call with a nested result, and a function call followed by a schema response. Assertions validate the answer, tool arguments, execution count, text deltas, and token totals.

Use `PROVIDER_CASES=text,schema,tools,tools-schema`, `PROVIDER_SURFACES=modern,runtime`, or `PROVIDER_MODES=complete,stream` to select a smaller run. `PROVIDER_TRANSPORTS=responses` explicitly tests the OpenAI Responses endpoint. `PROVIDER_EFFORT=none` tests non-reasoning OpenAI configurations on models that support it. `PROVIDER_THINKING=1` tests Claude's legacy thinking-budget option and its conversion to adaptive thinking on newer models.

Additional cases are `idle-tools` (tools are available but must not execute) and
`nested-schema` (nested objects, arrays, enums, nullable values, and property names
that also happen to be JSON Schema keywords).

Set `PROVIDER_REPORT` to a private path outside the repository for a JSON report containing case names, usage counts, and sanitized errors. Treat a failed assertion as a failure to investigate; do not count skipped models as passing.

## Copilot integration

The Copilot checks use the real `ReactChat` state, HTTP adapter, Runtime, and JSON/SSE serializers, with live provider responses. They test plain text, server tools, and client tools that resume the conversation. They also check that billing usage stays out of client HTTP responses.

```bash
RUN_PROVIDER_CHAT=1 \
PROVIDER_MODELS='openai:gpt-6-luna,anthropic:claude-haiku-5-5' \
node test/live/provider-chat.cjs
```

This checks the chat integration without opening a browser; it is not a visual or microphone test. Run the playground separately for those interactions.

## Settings that differ by provider

| Setting                                        | Behavior                                                                                                                                                                                |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `temperature`                                  | OpenAI reasoning modes and newer Claude models reject custom sampling. The SDK omits unsupported temperature values with a warning; supported models retain them.                       |
| `reasoningEffort: 'none'`                      | Supported by GPT-6 Luna and Sol; not by GPT-6.1 Sol or Astra. Tool calls with reasoning use Responses.                                                                                  |
| Claude thinking                                | Use `thinking: { type: 'adaptive' }` on newer Claude models. Legacy `thinkingBudget` / `{ enabled: true, budgetTokens }` remain accepted and become adaptive on supported newer models. |
| `responseFormat: { type: 'json_object' }`      | Native on OpenAI. Claude uses an instruction, so formatting remains best effort. Prefer JSON Schema for machine parsing.                                                                |
| `responseFormat: { type: 'json_schema', ... }` | Uses the provider's native schema API. Validate required business constraints locally; providers support different schema subsets.                                                      |
| `maxTokens`                                    | Includes reasoning tokens. A low limit may truncate before the final answer. Check completion status before parsing JSON.                                                               |
| Forced tools                                   | Some thinking modes and Claude models reject forced tool choices. A schema or `auto` tool choice may be appropriate, depending on the task.                                             |

Keep returned conversation messages intact when continuing tool calls. Claude thinking signatures and OpenAI encrypted reasoning are provider state; changing or discarding that state can break continuation. Replay metadata excludes raw billing usage and request diagnostics.

## Usage and caching

`generateText` and `streamText` report `promptTokens`, `completionTokens`, and `totalTokens`. `runtime.chat` is a server-side method and reports snake-case usage: `prompt_tokens`, `completion_tokens`, and `total_tokens`. Runtime's `onFinish` callback uses camel case. Client HTTP responses omit usage by default.

Tool-loop totals include every model call. Claude input totals include uncached input, cache creation, and cache reads. Token counts are not a price calculation: cached tokens and cache writes have different rates.

Enable Claude's automatic prompt caching with `anthropic(model, { cacheControl: true })` or `createAnthropic({ cacheControl: true })`. The provider's minimum prompt length and cache lifetime still apply.

```bash
RUN_ANTHROPIC_CACHE=1 node packages/llm-sdk/test/live/anthropic-cache.cjs
```

This uses a longer synthetic prompt to verify a real cache write followed by a cache hit. It does not test custom TTLs or manual block-level cache breakpoints.
